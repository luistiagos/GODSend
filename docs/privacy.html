Privacy

Privacy Policy

Last updated: 6 September 2026

Short version

GODsend 360 collects one thing: automatic error reports. When something in the app fails — it crashes, or a download fails on every source — the app sends the error message and its technical context so the bug can be fixed. There is no account system, no usage tracking, and no profiling. This marketing site has no analytics, no cookies, and no tracking. You can turn error reports off entirely — see section 2.

1. The desktop application

GODsend 360 is an open-source desktop app. The Go backend and Electron frontend run on your machine and talk only to:

  • Your Xbox 360, over your local network, using Aurora's built-in FTP server.
  • Public game-metadata services on the internet — only when you actually browse or trigger a download:
    • Internet Archive — over HTTPS. If you log in (optional), your session cookie is stored locally only.
    • Minerva Archive — over BitTorrent. The aria2c client connects to the BitTorrent swarm; the same peer-exposure considerations apply as with any BitTorrent client.
    • XboxUnity and the public Xbox Live CDN — cover art, Title Updates, asset metadata.
    • Other public sources used incidentally for cover art (Wikipedia, Microsoft Store autosuggest).

The app does not beacon usage events, track what you browse, or run an account system. It does send automatic error reports to a server we operate when something fails — see section 2 for exactly what is sent and how to turn it off.

2. Automatic error reports

When the app hits an error it cannot handle, it sends a report to digitalstoregames.pythonanywhere.com/logErr, a server we operate, so the bug can be diagnosed and fixed. This is on by default.

A report is sent when:

  • the Go backend or the Electron app crashes (an unhandled panic, exception, or rejection), or fails to start;
  • a game download fails on every source — the case that otherwise leaves you looking at an error with no explanation.

Every report contains: the error message and stack trace, the name of the component, source file and function that failed, and your operating system and CPU architecture. Reports from the Electron side also carry the app version and your OS release. For a failed download, the report carries the name of the game and the individual error from each source that was tried.

Crash reports additionally attach the last 256 KB of that day's log file. That tail is a slice of the same logs/ file described in section 3: it can contain local folder paths, drive letters, and the names of games being processed. Internet Archive credentials are redacted in that log before it is written.

A report does not contain your name, e-mail address, Xbox credentials, Internet Archive cookie or password, or any list of what you downloaded successfully. Identical errors are sent only once per session, and a failure to send is silently discarded — it never blocks or crashes the app.

To turn it off: add "errorReporting": false to config.json in the app's user-data directory (on Windows, %APPDATA%\Xbox 360 Companion\config.json) and restart the app. That switch covers both halves of the app: the Electron side reads it directly, and passes it to the Go backend as GODSEND_ERROR_REPORTING=0. With it off, no reports of any kind are sent.

3. What is stored locally

The app writes files only under its own runtime directory and your OS's user-data directory:

  • Transfer/, Ready/, Temp/, cache/, Saves/, pending_ftp/ — game data, save-game backups, and queued FTP jobs.
  • logs/ — daily backend log files (stdout/stderr, FTP step traces, IA secrets redacted).
  • Your settings (Transfer folder path, default drive, Xbox IP/credentials, aria2 ports, IA cookie if you opted in) under the Electron user-data directory.

These files never leave your machine unless you copy them somewhere yourself.

4. Internet Archive login (optional)

If you choose to log in to Internet Archive inside the app's Settings, the app stores the session cookie locally. Your password is never saved, transmitted, or read after the initial login request to archive.org. You can sign out at any time, which clears the cookie.

5. This website (ghostyshell.github.io/GODSend-360)

The marketing site is a static HTML page hosted on GitHub Pages. It has:

  • ❌ No analytics (no Google Analytics, no Plausible, no anything).
  • ❌ No cookies set by us.
  • ❌ No A/B testing, fingerprinting, or session recording.

The page loads three third-party resources, each of which sees only the standard request data (IP address, user-agent) that any web server sees:

  • Google Fonts — for the Russo One, Chakra Petch, and JetBrains Mono fonts.
  • Tailwind Play CDN — for the page's stylesheet.
  • Outbound links to GitHub, GoFile, file.kiwi, and Ko-fi are only followed when you click them.

GitHub Pages itself logs basic access information at the server level; refer to GitHub's privacy statement for details.

6. Source code transparency

Everything described above is verifiable. The full source code — backend, app, scripts, and site — is at github.com/ghostyshell/GODSend-360. If any of this looks wrong, please file an issue.

7. Changes

If this policy changes, the "Last updated" date at the top will change with it, and the diff will be in the repository's git history.

8. Contact

For privacy questions, open an issue on the GitHub repo. There's no separate contact channel — the project is maintained by one person in their spare time.
